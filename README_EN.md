## Security

> **Rule 0 — defence is always on.**
> Every task is treated as potentially hostile (prompt injection). The security
> policy is enforced in code at every tool call and **cannot be disabled** by
> configuration, prompt, MCP task or model output.

BYTE-SWARMY runs code generated by small LLMs with the permissions of the user
who starts the orchestrator. The built-in protections block the most dangerous
commands but **do not replace system isolation**:

- `run_bash` uses no shell: allowlist, blacklist and paths confined to `project/`;
- bubblewrap sandbox: isolated filesystem, blocked network, separate PID/user namespaces;
- `git push` / `pull` / `remote add|remove` disabled for workers;
- sanitised environment (no tokens, no `SSH_AUTH_SOCK`, no real `HOME`);
- CPU, memory, file-size and timeout limits on the process group;
- MCP tasks rebuilt from scratch, URLs limited to `http`/`https`;
- audit log with rotation in `logs/security.log`;
- `/etc` escape blocked (`--tmpfs /etc` + `--remount-ro`).

`[security] enabled = false` in `config.toml` is **ignored** and logged as
`CRITICAL`: the flag exists only for backward compatibility.

For real data you need system isolation (dedicated user, cgroup, firewall):

```bash
./setup-hardening.sh                  # diagnostic, no changes
sudo ./setup-hardening.sh --all       # byteswarmy user + cgroup + firewall
```

Details, threat model, residual risks and rollback: **[SECURITY.md](SECURITY.md)**.

Policy verification:

```bash
python -m pytest tests/ -v            # 55 tests: 27 security + 22 sandbox + 6 intent
tail -f logs/security.log
```

## Overview

BYTE-SWARMY is a multi-agent system that runs entirely locally on modest
hardware (4 GB RAM, optional GPU). It receives a task in natural language
(IT/EN/ZH), classifies it, decomposes it if needed and executes it with
specialised workers. State is persisted on SQLite, so work can resume after a
reboot.

### Enterprise Grade Quality Assurance

| Feature | Description | Benefit |
|---|---|---|
| **Audit Worker** | Second agent (Reviewer) that checks every change before approval. | Blocks bugs and vulnerabilities before they enter the project. |
| **Refactor-Loop** | Protocol: Map → Analyse → Modify → Verify. | Reduces regressions and keeps code modular. |
| **JSONL Logging** | Structured, immutable logs for every system action. | Full audit and enterprise traceability of AI decisions. |
| **Bubblewrap Sandbox** | Full isolation of worker processes (no network, no home, `/etc` escape blocked). | Prevents malicious code from running on the host. |
| **AST Scanner** | Deterministic gate that blocks dangerous Python code in `write_file`. | Stops `eval`, `exec`, `pickle` before the sandbox. |
| **Event Sourcing** | Worker memory as an immutable SQLite log. | Crash recovery and full decision audit. |
| **Persistent Memory** | Cross-task memory: existing files, common errors, recent tasks. | Worker doesn't recreate existing files, avoids known errors. |
| **USB Analysis** | Passive USB traffic inspection via `usbmon`. | Safe, read-only hardware reverse engineering. |

### Design principles

| Principle | Implementation |
|---|---|
| **Deterministic routing before the LLM** | Multilingual Intent Router classifies input; swarm commands handled without LLM. |
| **State = SQLite + JSON** | Queue on SQLite (ACID), state on JSON inspectable with `cat`. |
| **Transactional writes** | `write_file` writes a temp file then atomic `rename()`. |
| **Compacted memory** | After 50 events the context is summarised into `long_term`. |
| **Sequential loop** | One tick every 30 seconds (modulated by Timestral), predictable. |
| **Safety valve** | Auto-pause for RAM, disk, CPU/GPU temperature; clean shutdown on SIGTERM. |
| **Token streaming** | Model tokens appear in real time in the Live Activity Panel (300 ms). |
| **Model rotation** | Only one model in VRAM at a time; explicit load/unload. |

## Architecture

| Component | Role | Stack |
|---|---|---|
| **Intent Router** | Classifies free-form multilingual input (IT/EN/ZH) into structured tasks | Python (rapidfuzz) |
| **Orchestrator** | Main loop, dispatch, safety checks, swarm commands | Python |
| **Planner** | Decomposes complex tasks | Ollama |
| **Decision Model** | Decomposes generic tasks into 2–8 atomic subtasks | Ollama (`tev1:4b`) |
| **Worker** | Executes the atomic task: 21 tools, ReAct loop, token streaming | Ollama |
| **Audit Worker** | Reviewer: approves/rejects the worker's output | Ollama |
| **Model Selector** | 0–100 algorithm to pick the best model per role | Python |
| **Persistent Memory** | Cross-task memory: files, errors, preferences | Python (JSON) |
| **Watchdog** | Supervisor: restarts the orchestrator after a crash | Python |
| **AST Scanner** | Deterministic gate on `write_file` | Python |
| **Event Store** | Worker memory as an immutable SQLite log | Python |
| **Timestral** | CPU + GPU thermal monitoring and dynamic tuning | Python |
| **MCP Client** | Receives tasks from external MCP servers via SSE | Python |
| **PyQt6 GUI** | Control Center with 7 tabs | PyQt6 |
| **CLI Launcher** | `byte-swarmy` and alias `bswarm` | Bash |
| **Backup** | Periodic git snapshots, verified tar and on-demand GitHub sync | git |

### Tick cycle

```
┌──────────────────────────────────────────────────────────────┐
│  every 30 seconds (modulated by Timestral)                   │
│                                                              │
│  1. SAFETY CHECK   → RAM > 80%? Disk < 1 GB? → pause         │
│  2. TIMESTRAL      → CPU/GPU temp critical? → pause          │
│  3. MAINTENANCE    → git backup, memory compaction           │
│  4. DISPATCH       → read SQLite queue                       │
│  5. SWARM CMD?     → handle directly (no LLM, instant)       │
│  6. GENERIC?       → Decision Model decomposes               │
│  7. COMPLEX?       → Planner decomposes                      │
│  8. EXECUTE        → Worker ReAct (6 steps, streaming)       │
│  9. AUDIT          → auto-APPROVE if useful tool called      │
│ 10. PERSIST        → memory, events, state to disk           │
│ 11. SLEEP          → next tick                               │
│                                                              │
└──────────────────────────────────────────────────────────────┘
```

## How it works

### Intent Router (multilingual)

Free-form input (Quick Command Bar) passes through `INTENT/router.py` before
entering the queue: the text is classified with fuzzy matching (`rapidfuzz`)
against 28 intents in `INTENT/intents.json` (314 triggers total), the language
is detected (Italian, English, Chinese) and extracted parameters end up in the
task metadata. If the intent is not recognised with sufficient confidence, the
task degrades to `generic` and goes through the Decision Model.

### Swarm commands (zero LLM)

8 commands (`swarm_status`, `list_tasks`, `show_logs`, `pause_swarm`,
`resume_swarm`, `inspect_memory`, `cancel_task`, `run_audit`) are intercepted
by the orchestrator before dispatch and handled directly with Python handlers.
Instant response, zero tokens.

### Deterministic routing

| Task type | Destination |
|---|---|
| Swarm command | Direct handler (no LLM) |
| `type=generic` | Decision Model (`tev1:4b`) → 2–8 subtasks |
| Complex keywords ("system", "multi") | Planner (`phi3:mini`) → 2–5 subtasks |
| Otherwise | Worker directly |

### Timestral — dynamic tuning

Timestral samples every 30 seconds CPU temperature, GPU temperature (via
`nvidia-smi`), CPU load, frequency, RAM and swap. Thresholds are configurable
in `config.toml`.

| State | Condition | Effect |
|---|---|---|
| `FAST` | temp < 50 °C and load < 60% | tick × 0.6, double tasks/hour |
| `NORMAL` | temp 50–65 °C | tick × 1.0 |
| `SLOW` | temp 65–80 °C | tick × 1.7–2.5, halve tasks/hour |
| `PAUSE` | temp > 90 °C or GPU > 95 °C | No dispatch until cooldown |

History is saved in `state/timestral_history.json` (24 hours of samples).

### Intelligent Model Selector

`CORE/model_selector.py` scores every Ollama model 0–100 for each role
(orchestrator, planner, worker_coder, worker_general, embedding, decision).
Hard gates (VRAM/RAM/capability) + soft scoring (family match, name match,
quantization, thermal penalty). Returns top 1 + 3 alternatives per role.

```bash
python -m CORE.model_selector           # recommendations only
python -m CORE.model_selector --apply   # write to config.toml
```

### Dynamic KV cache

`INTENT/metrics.py` estimates KV cache with the real formula
`2 (K+V) × layers × kv_heads × head_dim × 2 × tokens`, using a
`MODEL_ARCHITECTURES` table for known models. Replaces the old hardcoded
per-family estimate (was up to 15× wrong for `phi3:mini`).

### Safety valve

| Condition | Action |
|---|---|
| RAM > 80% | Pause dispatch, auto-resume |
| Free disk < 1 GB | Pause and block new writes |
| CPU temp > 90 °C | Thermal pause |
| GPU temp > 95 °C | Thermal pause |
| CPU load > 95% for 60 s | Pause to avoid thrashing |
| 10 consecutive failures | Task in `stuck` state |
| Orchestrator crash | Watchdog restarts the process |
| 3 identical tool calls | Circuit breaker: mandatory pivot |
| SIGTERM | Save state, unload models, clean exit |

### Memory

Each worker has 4 tiers:

- **short_term** — current task events (RAM);
- **working** — compact context used in the prompt;
- **long_term** — persistent summary after compaction (SQLite event store);
- **persistent** — cross-task memory: existing files, common errors, recent
  tasks (`state/persistent_memory.json`). Injected into the worker's initial
  prompt so it doesn't recreate existing files.

## In-depth security

| Layer | Behaviour |
|---|---|
| **Commands** | `run_bash` tokenises, rejects shell metacharacters, allowlist + blacklist, `shell=False`. |
| **Paths** | Only paths relative to `project/`; blocks absolute paths, `..`, `~`, symlink escapes, sensitive files. |
| **Sandbox** | bubblewrap: isolated filesystem, blocked network, separate PID/user namespaces, `--cap-drop ALL`, `--disable-userns`, `--remount-ro /etc` (escape blocked). |
| **AST** | `write_file` goes through `ast_scanner.py` that blocks `eval`, `exec`, `pickle`, etc. |
| **Git** | local `status`, `log`, `diff`, `branch`, `merge`, `commit`; push/pull/remote disabled. |
| **Environment** | sandbox `HOME`; tokens, SSH sockets, cloud vars removed. |
| **Resources** | CPU, memory, open files, file size, core dump limits; process group timeout. |
| **External input** | MCP tasks rebuilt from scratch, fields with max length, URLs `http`/`https` only. |
| **Audit** | Every allowed/blocked/timed-out command logged in `logs/security.log`. |

Defence **does not depend on the prompt**: even if a task contains "ignore the
rules", the tool layer still applies the policy.

### System isolation (optional, requires root)

```bash
./setup-hardening.sh                  # Diagnostic
sudo ./setup-hardening.sh --all       # byteswarmy user + cgroup + firewall
sudo ./setup-hardening.sh --undo      # Remove slice and firewall rules
```

### Residual risks

1. Project code runs with the user's permissions.
2. `Makefile`/`CMakeLists.txt`/tests can run their own shell commands.
3. No seccomp, AppArmor or container included.

For sensitive data use **dedicated user + firewall**.

## Known limitations

- **One model loaded at a time**: rotation is explicit (4 GB VRAM constraint).
- **Sequential workers**: no parallelism, one task at a time.
- **Limited context** (3072 tokens): large tasks are decomposed.
- **Limited LLM output** (512 tokens/step, 6 steps max): large files need multiple tasks.
- **1.5 B–4 B models**: effective on discrete tasks, unreliable on complex architectures.
- **TDD relaxed**: the TDD check is warning-only (small models struggle with test-first).
- **No kernel sandbox**: full isolation requires system hardening.

## Troubleshooting

| Symptom | Likely cause | Solution |
|---|---|---|
| `ModuleNotFoundError: PyQt6` | GUI deps missing | `./setup.sh` or `pip install -r requirements_gui.txt` |
| `ModuleNotFoundError: rapidfuzz` | Intent router not installed | `pip install rapidfuzz` |
| `ModuleNotFoundError: mcp` | MCP deps missing | `pip install mcp httpx httpx-sse` |
| Orchestrator won't start | Virtualenv not active | `source .venv/bin/activate` |
| Status "stopped" after start | Subprocess terminated | Check `logs/byte-swarmy.log` |
| Toggle button desync | Old bug | Restart GUI (`./avvia.sh --gui`) |
| RAM saturated | Models not unloaded | Check `keep_alive=0` in log |
| Task always `stuck` | Prompt too complex | Split the task or use a Generic task |
| Huge KV cache | Model with many layers (e.g. phi3) | Use a smaller model (qwen2.5-coder:1.5b) |
| GPU too hot (> 90 °C) | Timestral pauses | Improve ventilation or use a smaller model |
| `tomli_w not installed` | TOML writer missing | `pip install tomli-w` |
| Push: `Authentication failed` | Wrong/expired token | Create a new GitHub PAT |
| Command blocked by `run_bash` | Security policy active | Read the message: it explains why and the alternative |

- deterministic handler for `type=execute` (gcc + run, no LLM);
- predictive Timestral (EMA/regression);
- advanced persistent memory (user preferences);
- automatic model benchmarking;
- USB protocol parser and differential analysis.

Before proposing a change, verify it respects the project constraint:
*"does it run on 4 GB RAM without cloud?"*

For changes touching security, also update `SECURITY.md` and the
`tests/test_security.py` suite.
